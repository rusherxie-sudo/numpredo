# numpredo SEO 长期增长方案

> 制定日期：2026-09-03  
> 适用周期：未来 12 个月，按季度滚动修订  
> 北极星：Google Search Console 自然搜索点击持续增长  
> 次级渠道：Bing 自然搜索，用于获得增量流量和更快验证需求

## 一、结论先行

numpredo 当前不是缺功能，也不是缺基础技术 SEO。站点已经拥有 4,395 道标准题、毎日7問、OCR 求解器、打印 PDF、技巧图解、可玩キラー/対角線、16×16 求解器和原创研究；构建、结构化数据、真实 lastmod、重定向与 Core Web Vitals 也已有工程保障。

当前真正的增长约束有四个：

1. **实时决策数据没有形成固定运营节奏**：过去根据 GSC/Bing 做过多轮优化，但还需要固定为每周机会队列，而不是阶段性集中改站。
2. **可索引内容面仍然较窄**：当前 sitemap 约 63 个 URL，其中指南 28 个。4,395 道题是产品资产，不应粗暴全部索引，但需要用高质量专题、精选题集和真实解法数据扩大搜索覆盖。
3. **域名权威仍是排名上限**：站内质量较强，但持续获得日本语境下的真实引用、链接和品牌搜索仍是长期必做项。
4. **过去两个月修改频率很高**：同一批页面反复改 title、description 和文案，后续必须进入“改动—等待—复盘”的实验纪律，避免在 Google 尚未稳定评估前继续改写。

未来 12 个月的主线应从“继续堆功能”切换为：

> **收割已有曝光 → 扩大高质量主题覆盖 → 用原创数据获取权威 → 依据 GSC 循环更新。**

本方案按 **AI 产能近似无限** 设计，不再在人力工时之间做固定占比分配。五条工作线可以并行运行：GSC 机会收割、全市场关键词发现、内容集群生产、数字公关、技术监控。真正需要控制的是发布，而不是研究或生产，因为 Google 的抓取、索引、信任积累和实验反馈时间仍然有限。

采用三层产能漏斗：

| 层级 | AI 执行方式 | 是否限量 |
| --- | --- | --- |
| 发现层 | 全量拉取 GSC/Bing query、竞品排名词、Suggest/PAA、论坛问题并持续聚类 | 不限量 |
| 生产层 | 为所有合格词生成 brief、SERP 对照、独有素材方案、内链图和日语初稿 | 不限量，但不等于自动发布 |
| 发布层 | 通过意图、原创性、防薄、事实、内链和技术门后分批上线 | 由索引与排名反馈动态放量 |

AI 的优势应用在“把所有机会研究透、把所有候选准备好、把监控自动化”，而不是一次性向 Google 倾倒大量相似页面。

## 二、目标体系

### 2.1 先建立真实基线

方案启动日从 GSC、GA4 和 Bing 导出最近完整 28 天，记为 `B0`。所有目标以此为基线，避免沿用 7 月旧数据。

必须记录：

| 类别 | 指标 |
| --- | --- |
| 北极星 | Google 28 天自然点击、周均自然点击 |
| 覆盖 | 有曝光 query 数、有曝光页面数、有效索引页数 |
| 排名 | Top 3 / Top 10 / Top 20 非品牌 query 数，排名 4–20 的机会词数 |
| CTR | 全站 CTR；重点页按 query、设备拆分的 CTR |
| 质量 | 非品牌点击占比、各主题簇点击占比、自然流量参与度 |
| 权威 | 新增 referring domains、获得自然链接的页面数、品牌词曝光 |
| 健康 | CWV、404、重定向、重复 canonical、抓取异常、sitemap 差异 |

### 2.2 12 个月目标

以 `B0` 为分母，采用目标而非承诺：

| 时间 | Google 点击目标 | 先行指标 |
| --- | ---: | --- |
| 90 天 | `2 × B0` | Top 10 非品牌词 ≥ 1.8 倍；有效索引的高质量页增加 12–20 个 |
| 180 天 | `3.5 × B0` | 至少 3 个主题簇每月稳定带来点击；新增 10 个相关引用域 |
| 365 天 | `6 × B0` | 流量不再由单一 solver 页贡献超过 40%；新增 25 个相关引用域 |

设三个判断区间：低于目标 70% 为红灯，70%–100% 为黄灯，高于目标为绿灯。红灯时不靠加大发文量解决，先检查索引、意图、竞争强度和链接缺口。

## 三、增长战略

### 3.1 第一引擎：收割 Google 已经给出的机会

每周从 GSC 生成四个队列：

1. **排名 4–10**：优先争 Top 3，通常先优化答案结构、内链和 CTR。
2. **排名 11–20**：最高 ROI 队列，判断是内容不完整、意图不匹配还是权威不足。
3. **高曝光低 CTR**：只在排名和展现已稳定时测试 title/description；一次只改一个主变量。
4. **页面已有曝光、query 尚未充分回答**：补入现有页面；只有搜索意图明显独立时才新建页面。

机会评分统一为：

```text
机会分 = 展示潜力 30% + 当前排名可推进度 25% + SERP 可攻克度 25%
       + 业务/站点契合度 15% + 内链与资产复用度 5%
```

入选本月执行队列的事项必须写清：目标 query、目标 URL、当前 28 天数据、要解决的缺口、预计观察日。没有这五项不改页面。

### 3.2 第二引擎：建立全市场关键词宇宙

选题边界不是“当前已经覆盖的关键词”，而是日本市场中所有与数独/ナンプレ相关、且站点有能力给出最好答案的搜索需求。AI 持续维护六层词库：

| 层级 | 例子 | 页面策略 |
| --- | --- | --- |
| 核心玩法 | ナンプレ、数独、無料、問題 | 强化首页、play Hub 和难度页 |
| 任务型需求 | 解く、答え合わせ、画像、印刷、作る | 工具页、打印页和任务指南 |
| 学习型需求 | ルール、コツ、テクニック、行き詰まり | Guide Hub、技巧页、练习页 |
| 人群与场景 | 初心者、子ども、高齢者、学校、介護 | 独有版式、内容和可下载资产 |
| 变体与规格 | キラー、対角線、不等号、16×16、6×6 | 变体规则、工具、可玩页 |
| 问题与实体 | 発祥、名前、脳トレ、アルゴリズム、唯一解 | 事实型指南、原创研究和开发内容 |

词源同时覆盖：

- GSC/Bing 中当前有曝光的词；
- SEMrush 中全部相关竞品的自然排名词与 Keyword Gap；
- Google Suggest、PAA、相关搜索及其递归扩展；
- Yahoo!知恵袋、教えて!goo、YouTube、App 评论中的真实问题表达；
- 日语同义表达、错拼、片假名/汉字/英文技巧名，但不为纯同义词重复建页；
- 季节与场景词，如假期打印、学校教材、介护活动；只有稳定或可预测需求才建常青页。

每个词都进入统一聚类，不预先限制数量。聚类输出四种动作：映射现有页、补强现有页、新建独立页、舍弃无关/不可赢词。先完成整个关键词地图，再按机会分和内容资产能力决定发布顺序。

### 3.3 第三引擎：围绕已验证主题建设集群

不做平均铺量，优先级按现有验证信号排序。

#### A. 自动解答与诊断集群（最高优先）

核心页：`/tools/solver/`、`/tools/candidate-checker/`、`/guide/when-stuck/`、`/guide/newspaper/`、`/guide/solving-examples/`、`/variants/16x16/`。

增长方向：图片/相机输入、答え合わせ、途中盘面、错误与矛盾诊断、唯一解/複数解、下一手提示、报纸题解答、16×16 解答。先在 GSC 中验证 query 簇；相同工具意图尽量由主工具页承接，避免为同义词复制落地页。

目标：保住 OCR 优势，并把流量从单一“画像/カメラ”扩展到诊断、答え合わせ和次の一手等相邻意图。

#### B. 打印与教育集群（高优先）

核心页：`/print/`、五档打印页、`/print/senior/`、`/print/techniques/`、`/print/blank/`、`/guide/for-kids/`。

增长方向：答え付き、A4、大きい文字、高齢者、子ども、学校、介護施設、技巧专项练习和不同题量。新页面必须提供真正不同的 PDF、版式、对象或使用场景，不能只替换关键词。

目标：形成可下载、可打印、可被学校/介护/教育资源页引用的资产型内容。

#### C. 解法与技巧集群（高优先）

核心页：初级/中级/上级/难问指南、技巧总表、10 个技巧图解页、专项练习页。

增长方向：根据 GSC 补齐用户实际搜索的日语别名、识别方法、错误例和练习；新增技巧页前先验证搜索需求、引擎支持和独有图解能力。

目标：从“技巧词有页面”升级为“定义—识别—图解—练习—真实题例”的完整学习路径。

#### D. 免费游戏与每日题集群（中优先）

核心页：首页、`/play/`、五档页面、`/daily/`、`/daily/archive/`。

增长方向：無料、問題集、難易度、毎日、登録不要、広告体验等词簇。重点是提升核心页排名和复访，不为每日日期创建大量薄页面。

目标：降低 solver 单页依赖，让 play/daily 成为第二个稳定流量入口。

#### E. 变体与原创研究集群（选择性投入）

优先キラー、対角線和已有工具能力的 16×16；6×6、不等号仅在数据增长时扩张。原创研究页应持续发布可复用图表、CSV、方法说明和年度更新，服务数字公关与自然引用。

### 3.4 第四引擎：可控扩页，而不是题库全量索引

当前 `indexable-puzzles.json` 为空，说明已主动收缩题号页索引。这一判断应保持，不能直接把 4,395 道题全部开放索引。

精选题页重新开放必须通过以下门槛：

- GSC 已出现题号、难度或具体问题型需求，或所属集合页已经有稳定流量；
- 每页有引擎生成的真实解法路径、关键步骤图、难度依据和独有 FAQ；
- 页面不与难度页、打印页和相邻题页争同一主 query；
- 每批只开放 10–20 页，观察 6–8 周；
- 批次有效索引率 ≥80%，且至少 20% 页面获得非零曝光，才扩大下一批；
- 若大量为 Crawled/Discovered currently not indexed，停止扩页并回收低价值 URL。

更优先的规模化形式是：按明确意图制作精选题集、技巧训练集或打印集合页，一页承载一组真正有差异的题，而不是“一题一页”。

### 3.5 第五引擎：日本语境下的权威与外链

不购买批量链接，不做无关目录站，不交换全站 footer 链接。AI 可以无限扩展对象发现、页面匹配和个性化材料准备，但真实链接仍取决于对方是否认为资产值得引用。阶段目标从每月 2–3 个相关引用域起步，获得稳定回复率后继续放大。

可长期执行的四类动作：

| 资产 | 目标对象 | 外联切入点 |
| --- | --- | --- |
| 高龄者大字打印、介护可用 PDF | 介护施設、地域包括支援、レクリエーション资料站 | 免费、可打印、许可清晰、无需注册 |
| 儿童/学校练习材料 | 学校教师、学童、家庭教育博客 | 年龄分层、答案付き、课堂可用 |
| 数独研究数据与图表 | 数学教育、编程、数据分析作者 | 可引用 CSV、图表、方法透明 |
| 求解器与算法指南 | 开发者、算法课程、技术博客 | 可运行工具、唯一解判定、实现说明 |

每月流程：全量建立潜在对象库 → 自动匹配最相关的站内资产与对方具体页面 → 人工或严格质量门审核 → 分批发送高度个性化的日语邮件 → 追踪一次 → 记录获得链接、提及或拒绝原因。首月可从 30–50 个高相关对象开始，按回复率扩大；不群发模板，不为追求数量触发垃圾邮件风险。

同时经营无链接提及：监测 `numpredo`、研究图表标题和资源名；对真实引用但未链接的页面礼貌请求补链。

## 四、前 90 天执行计划

### 第 1–2 周：冻结基线与清理决策系统

- 导出 GSC/GA4/Bing 最近 28 天和前一周期对比，建立 `B0`。
- 按 query × page 检查品牌词、设备和国家，避免平均排名误导。
- 核对 sitemap 63 个 URL、有效索引页、被排除原因、canonical、404 和旧 URL 信号。
- 将 7–8 月已频繁修改的核心页列为观察组，除明显错误外冻结 28 天。
- 建立机会 backlog，每项必须有数据、URL、假设、动作、观察日和结果。

交付：基线表、索引差异表、Top 20 机会清单、页面冻结清单。

### 第 3–4 周：只做 5 个最高 ROI 实验

- 从排名 4–20 中选择最多 3 个页面做内容/内链增强。
- 从高曝光低 CTR 中选择最多 2 个页面做摘要实验。
- 每页只设一个主 query 簇，先检查是否存在关键词蚕食。
- 从 5–8 个强相关页面增加上下文内链，锚文本自然变化。
- 提交 sitemap；仅对关键新页或重要修复页请求索引。

交付：5 张实验卡；28 天后逐项判定赢、平、输。

### 第 2 个月：发布第一个完整内容集群

根据 B0 选择“打印/教育”或“求解器诊断”中数据更强的一簇：

- 1 个 Hub 页升级；
- 2–3 个意图独立、非同义词拆页的 Spoke；
- 1 个可下载/可引用资产；
- 完成 Hub ↔ Spoke 双向内链；
- 启动第一轮 10 个高相关对象外联。

生产层可以同时准备所有集群，但发布层先将胜出集群按 8–12 页作为一批上线。每批页面都必须有独立意图和独有资产；上线 2–4 周后根据抓取与初始曝光决定下一批规模。若有效索引率 ≥80%、非零曝光页比例持续达标，可从 12 页逐步放大到 20、40 页一批，而不是设置固定月上限。

### 第 3 个月：验证扩张模型

- 复盘第一个集群的索引率、query 覆盖、Top 20 数和点击。
- 赢：沿同一集群扩 3–5 页；平：补 SERP 缺口与外链后再观察；输：停止扩张。
- 选择性测试一批 10–20 个精选题页，或改做 1–2 个精选题集页。
- 发布或更新一项原创研究资产，并做第二轮数字公关。
- 完成第一次季度技术与内容审计。

## 五、长期运营节奏

### 每周：自动全量分析 + 一轮发布决策

周一：

- 对比最近 7 天与前 7 天，同时查看 28 天趋势，排除日波动；
- 检查点击异常、索引异常、核心页丢排名和品牌/非品牌结构；
- 更新排名 4–20、高曝光低 CTR、新 query 三个队列；
- AI 完成全部机会的聚类和评分；发布队列优先处理高分项，不限制研究与草拟数量。

周中：并行完成内容更新、新页面、内链图、SERP 对照和外联材料。周五依据质量门决定发布批次，记录目标 query 和下次观察日。不要把“发布篇数”当 KPI。

### 每月：一次完整飞轮

1. 固化 28 天快照并与前期、去年同期比较。
2. 按主题簇而非单页复盘点击、曝光、排名和 CTR。
3. 全量处理近失词诊断；所有低风险站内补强可执行，title/主意图类实验仍分组隔离。
4. 依据上批索引与曝光数据动态发布下一批高质量页面，不设人工产能上限。
5. 全量发现外联对象并分批发送高质量个性化联络，目标从每月 2–3 个相关引用域逐步放大。
6. 检查索引、CWV、404、重定向、结构化数据和 sitemap。
7. 将新 query 和竞品缺口重新评分，进入下月 backlog。

### 每季度：方向调整

- 全站内容盘点：保留、合并、重写、noindex 或删除；
- 检查主题簇是否建立流量，是否过度依赖单页或单 query；
- 复核竞品新增页面、SERP 形态、AI Overview/PAA/视频/图片结果变化；
- 决定下季度的主攻集群；多个已通过验证的集群可并行扩张；
- 检查自然链接、品牌搜索、直接流量是否同步增长；
- 根据实际产能重设目标，不把未完成任务机械顺延。

## 六、页面生产与更新标准

### 6.1 新页面准入

同时满足以下条件才创建：

1. 有 GSC、Bing、SEMrush、Google Suggest/PAA 或竞品流量中的至少两个信号；
2. SERP 意图与现有页面明显不同；
3. 能提供独有内容、交互、数据、SVG、PDF 或真实题例中的至少一种；
4. 上线时已有至少 3 条相关内链来源和 2 条指向下游页面的链接；
5. 能明确写出 28/56 天后的成功判定。

### 6.2 旧页面更新

优先补“缺失信息”，不是无理由重写全文。建议顺序：搜索意图 → 首屏直接答案 → 独有证据/例子 → 标题与描述 → 内链 → Schema。

同一 URL 的主要 SEO 元素改动后至少观察 28 天；大改观察 6–8 周。明显事实错误、坏链和索引故障不受冻结期限制。

### 6.3 防蚕食规则

- 一个主意图优先一个主 URL；
- 同义词先合并到现有页，不因关键词表述不同就拆页；
- 新页发布前在 GSC 查目标 query 已由哪个 URL 获得曝光；
- 两页长期轮换排名时，比较意图后合并、canonical 或重新划分主题；
- Hub 页覆盖广义词，Spoke 页只承接具体且独立的问题。

## 七、实验与停止规则

每次 SEO 改动用实验卡记录：

```text
目标 URL：
目标 query 簇：
基线窗口：最近完整 28 天
问题判断：覆盖 / 排名 / CTR / 索引 / 权威
本次唯一主变量：
发布日期：
首次观察：第 14 天（只看异常）
正式判定：第 28 天；大改第 56 天
结果：赢 / 平 / 输
后续：扩大 / 保持 / 回滚 / 再验证
```

判定原则：

- **赢**：目标 query 点击或有效曝光明显增加，且没有引发相邻核心词显著下跌；
- **平**：曝光与排名基本不动，先判断链接/权威缺口，不立即再次改标题；
- **输**：目标指标持续下降且排除季节、算法和全站波动后，回滚或重构；
- 新集群连续 3 个月没有形成有效索引与非零曝光，暂停继续生产；
- 新功能若不能提升搜索覆盖、自然入口转化或回访指标中的任一项，不再追加投入。

## 九、明确不做

- 不一次开放数千道题目页索引；
- 不按“每周必须发几篇”制造薄内容；
- 不为同义关键词建立多个高度相似页面；
- 不因排名短期波动连续修改 title；
- 不把 FAQ Schema、`llms.txt` 或所谓 AI 提交当作主要增长杠杆；
- 不用虚构更新时间刷新 lastmod；
- 不买批量垃圾外链、不做无关站群；
- 不在没有需求证据时继续开发纯留存功能；
- 不只看全站平均排名，所有决策回到 query × page × device × country。
